# Languages (Phase 6)

The interface is available in English (`en`), Hindi (`hi`), Bengali (`bn`), Odia (`or`), Telugu
(`te`) and Marathi (`mr`): the API's `preferred_language` values.

## Which language shows

- **Signed out** (login, raise a grievance, track a grievance): the small switcher at the top of the
  page. The choice is kept in this browser (`localStorage`, key `smg.lang`); the default is English.
- **Signed in:** the account's saved `preferred_language` wins over the browser's choice. The
  **Profile** page (sidebar link "Profile and language", every role) shows name, role, company,
  area and mine, and lists the six languages in their own scripts. Choosing one saves it with
  `PATCH /v1/users/me` and switches the whole interface at once, without a reload.
- Signing out returns to the browser's choice.

`<html lang>` follows the UI language, so screen readers pronounce the text correctly.

## Where the text lives

- `frontend/src/i18n/locales/<lang>.json`. `en.json` is the source; the other five are
  translations of it, with the same keys.
- Every UI string goes through `t()` / `useT()` (`frontend/src/i18n/t.js`). This includes chart
  axes, legends and tooltips, map controls and credits, alerts and errors rendered from the API's
  `{code, params}`, and the labels of coded data: violation types, incident causes, obligation
  titles, evidence types and frequencies, and audit field names.
- **Stays in the original language:** legal citations and the verbatim quotes of obligations (act,
  section, quote, source file and page). The labels around them are translated. People's own words
  also stay as written: grievance texts (with their language labelled), notes and reasons. So do
  names: mines, districts, companies, people.

## Checks (part of `api\run_tests.bat`, and `npm run i18n:check` in `frontend/`)

- `scripts/check_locales.mjs` fails if any locale lacks a key of `en.json` or has one `en.json`
  does not. It also fails if a value's `{{placeholders}}` differ from English, or if
  `"_meta": {"reviewed": ...}` is missing. It reports how many values are still identical to
  English.
- `scripts/check_hardcoded_strings.mjs` parses the frontend and fails on UI text written directly
  in JSX, in text-bearing props (`label`, `title`, `placeholder`, `aria-label`, `context`, ...), or
  in tab lists, toasts and default props.
- `node scripts/browser_check.mjs phase6 --side-tabs` screenshots the main screens in all six
  languages with the network blocked. It probes each screen for clipped or spilling text
  (`docs/screenshots/phase6/overflow.json`); `--strict` fails on any finding.

To add a string: add the key to `en.json`, use it through `t()`, add it to the five other locales,
and run the checks.

## Numbers and dates

`frontend/src/utils/format.js` formats through `Intl` in the UI language as `<lang>-IN` with Latin
digits (`-u-nu-latn`):
- Indian grouping (`17,04,240`) and the language's own month names (`28 सित॰ 2026`) in every
  locale;
- scores, counts and codes keep the digits readers see on ids.

Bengali and Marathi default to their native digits; switching is one constant (`DIGITS`).

A browser may ship no `Intl` data for a language. Chromium (Edge, Chrome) has none for Odia, and
formats Odia dates in English ("30 Jun") without any error. For such a language `format.js` formats
as `en-IN`, which keeps Indian grouping, and takes the month names from the locale file
(`date.monthShort`, `date.monthLong`). The Phase 6 browser check fails if an English month name
appears on any non-English screen.

## Fonts

Noto Sans Devanagari (Hindi, Marathi), Bengali, Oriya (Odia) and Telugu are bundled with the app
(`@fontsource/*`, weights 400-700), and nothing is requested from a font service. They follow Inter
in the font stacks (`--font-indic` in `theme.css`, also in the mono stack), so Latin text keeps
Inter. Each face declares its unicode range, so a browser downloads only the scripts it renders. The
Phase 6 browser check runs with every off-machine request blocked and confirms the Noto faces load.

## Translation status

The five translations are **drafts** made with Claude on 2026-09-28, using the agreed terms of
`data/reference/glossary.csv`. Each file says `"_meta": {"reviewed": false}`, and the Profile page
says so when a non-English language is chosen. They need review by native speakers who know mining
vocabulary; after a review, set `reviewed` to `true` in that file.

## Roadmap: user content

User-entered content is **not translated**: grievance texts, notes, reasons and review comments are
stored and shown as written, and a grievance shows the language it was written in. Machine
translation of that content (for example, a regulator reading an Odia grievance in English) is
roadmap, not part of this phase. It would show a labelled translation next to the original, never
instead of it.
